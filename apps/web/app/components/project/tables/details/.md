# `/process` Endpoint Breakdown

## Overview

The `/process` endpoint is designed to handle the full pipeline of validating and inserting data from a spreadsheet file into the database. It publishes a task to a message queue (MQ), and a worker processes the file asynchronously.

---

## HTTP Method & Path

- **POST** `/process`

---

## Purpose

- Validates and inserts data from an uploaded spreadsheet file into the database.
- Publishes the task to a message queue; the worker performs the actual processing.

---

## Parameters

All parameters are sent as form data (multipart/form-data):

| Name            | Type      | Required | Description                                         |
|-----------------|-----------|----------|---------------------------------------------------- |
| spreadsheet_file| UploadFile| Yes      | The spreadsheet file to be processed                |
| project_id      | string    | Yes      | The ID of the project                               |
| table_name      | string    | Yes      | The name of the table to insert data into           |
| overwrite       | bool      | No       | Whether to overwrite existing data (default: False) |

**Contextual dependencies (injected by FastAPI):**

- `request`: The HTTP request object (used for trace headers)
- `current_user`: The authenticated user
- `publisher`: Publisher dependency for MQ
- `database_client`: Database client dependency
- `project_service`: Service to fetch project DB credentials
- `idempotency_service`: Service to ensure idempotency

---

## How It Works

1. **Permission Check:**
   Verifies if the user has permission to process uploads for the given project.

2. **DB Credentials:**
   Fetches the database URI for the project.

3. **Trace Headers:**
   Extracts trace headers from the request for distributed tracing.

4. **Idempotency Service:**
   Calls `idempotency_service.process_task` to:
   - Create a task in the database (status: pending)
   - Publish a validation/insertion request to RabbitMQ
   - Update the task status to published
   - Optionally update a cache (best effort)

5. **Response:**
   Returns an API response with task status and IDs.

---

## Possible Errors

- **403 Forbidden:**
  If the user does not have permission to process uploads for the project.

- **400 Bad Request:**
  - If the file is missing, empty, or has no filename/content type.

- **500 Internal Server Error:**
  - If there is a database error (e.g., connection issues).
  - If publishing to RabbitMQ fails.
  - If any unexpected exception occurs.

- **202 Accepted:**
  If a task with the same idempotency key is already in progress (idempotency window).

---

## Example Response

```json
{
    "status": "accepted",
    "code": 202,
    "message": "Validation/Insertion request published successfully",
    "data": {
        "task_id": "some-task-uuid",
        "project_id": "your-project-id"
    }
}
```

---

## Notes

- The endpoint is asynchronous: the actual validation and insertion are performed by a background worker.
- Idempotency is enforced: duplicate requests with the same file/context within a time window will not trigger duplicate processing.
- Trace headers are supported for distributed tracing.
